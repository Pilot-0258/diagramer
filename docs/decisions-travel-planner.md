# 行程图：需求与架构决策记录

最后更新：2026-10-21

本记录保存已确认的结论与理由。后续若改变决策，应追加新记录，不覆盖历史背景。

## 已确定

| 主题 | 结论 | 理由 |
| --- | --- | --- |
| 产品目标 | 面向个人及朋友的本地旅行计划工具。 | 当前不是商用产品，最重要的是可靠、好维护、数据留在本机。 |
| 第一版范围 | 结构化录入、多日时间表、本地保存、JSON 导入导出、PNG 和打印/PDF。 | 先解决最核心的“整理清楚并方便分享结果”。 |
| 输入方式 | 第一版使用结构化表单；未来可增加文字解析。 | 表单结果确定、可测试且不依赖 AI；字段模型又能承接未来解析草稿。 |
| 排程方式 | 按用户填写的准确起止时间排序与呈现，只提示重叠，不自动优化。 | 自动排程和真实交通耗时是独立且复杂的能力，不应阻塞 V1。 |
| 时间规则 | 日期保存为 `YYYY-MM-DD`，时间保存为 `HH:mm`；行程时区默认 `Asia/Shanghai`；不接受跨午夜事件。 | 中国大陆行程以本地墙上时间为主，避免 UTC 转换产生日期错误。 |
| 时间表版式 | 按天纵向排列的“行程卡 + 表格”混合版式。 | 兼顾桌面阅读、手机适配、长图导出与打印，不偏海报或高密度表格。 |
| 数据保存 | 使用浏览器 `localStorage` 自动保存，并提供版本化 JSON 备份。 | V1 只有纯文本行程，数据量小；无需数据库和服务端。清除浏览器数据会丢失记录，因此必须可导出备份。 |
| 本地地址 | 开发和本地预览固定为 `http://127.0.0.1:4173`。 | `localStorage` 按来源隔离，固定协议、主机和端口才能稳定找到旧数据。 |
| 技术栈 | React、TypeScript、Vite，第一版纯前端。 | 生态成熟、适合复杂表单和动画地图，同时避免 V1 引入数据库与服务端。 |
| 分享模式 | 每个朋友运行独立本地副本，通过 JSON 交换行程。 | 不引入账号、云数据库、权限与多人编辑冲突。 |
| 图片导出 | 使用 `html-to-image` 生成整趟行程 PNG；浏览器打印生成 PDF。 | 与 HTML 时间表保持同一份样式，避免另维护一套海报排版。 |
| 隐私 | V1 不发起地图或 AI 网络请求，不使用云同步和统计服务。 | 本地优先；未来外发数据必须由用户明确触发并先预览结果。 |
| 媒体文件 | 图片、音频、视频及生成产物不进入 Git。 | 遵循项目约定；界面图标使用代码内 SVG，不保存二进制素材。 |
| Git 节奏 | 每完成一个小功能先等待用户验收，确认后才提交；未提交前不开始下一个功能。 | 保证每个阶段可回退、可审阅，避免未确认的大范围改动。 |

## 地图与后续能力

| 主题 | 结论 | 理由 |
| --- | --- | --- |
| 地图地区 | 主要服务中国大陆。 | 地址、坐标体系和服务可用性与国际地图方案不同。 |
| 默认供应商 | 通过适配层优先接入高德，但不把时间表数据绑定到高德。 | 高德 JS API 官方支持地点搜索、地理编码及驾车、公交、步行、骑行规划。 |
| 动画方式 | 提供全行程与单日两种范围，按行程顺序逐段高亮、移动镜头并绘制路线。 | 比车辆图标更清楚，也减少对真实耗时模拟的误导。 |
| 交通段来源 | 同时支持明确录入的交通事件，以及同日相邻有坐标活动之间的推断路线。 | 有时需要把交通耗时排进时间表，有时只希望地图补出移动关系。 |
| 地图密钥 | 地图阶段增加本机 Node 小代理，高德 Key 与安全密钥进入未提交的 `.env`。 | 高德官方建议通过代理保护安全密钥；纯前端或分享开发者的 Key 会增加滥用风险。 |
| 文字解析 | 未来使用独立 `ItineraryTextParser` 适配器，结果先作为草稿预览，确认后才保存。 | 解析可能出错，且可能把旅行内容发送给外部服务，不能静默修改或上传。 |

## 待定问题

- 地图功能正式开工前，需重新核对高德最新授权、配额和本地代理要求。
- 文字解析功能正式开工前，再决定使用哪家 AI、是否支持本地模型及具体隐私提示。
- 若未来路线数据使 `localStorage` 容量不足，再评估迁移 IndexedDB，而不是在第一版提前引入。
